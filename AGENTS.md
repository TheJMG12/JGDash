# AGENTS.md

## Cursor Cloud specific instructions

- This is a **static multi-page site** (no npm app, no build). From `/workspace`, serve with `python3 -m http.server 8765` (or any static server).
- **Goals UI:** open `main.html` — fully self-contained (inline CSS/JS, `localStorage`). Works on `file://` for demos.
- **Hub:** `index.html` bento grid → `main.html`, `training.html`, `health.html`, `media.html`, `finance.html`, `projects.html`.
- **Media:** `media.html` hub is Capture/Inbox + Library + RSS (news/YouTube/Reddit). Spaces: `visual-bookmarks.html`, `watchlist.html`, `reading-list.html`. Pasting a URL auto-fills via `JGMedia.enrichMeta` (YouTube oEmbed, Microlink, Reddit JSON proxy). Library cards open the source URL in a new tab. Data in `localStorage` `jg_media_data_v1` (clear that key to reset sample content). Uploaded image blobs optional in IndexedDB `jg_media_images_v1`. RSS uses rss2json / allorigins proxies — some feeds may fail CORS.
- **Finance:** `finance.html` — budgeting, purchases, goals, investing, stock analyzer. Manual finance data in `localStorage` `jg_finance_data_v1`. Live quotes via Finnhub when `JGDASH_CONFIG.FINNHUB_API_KEY` is set; otherwise sample/demo market data. Chart.js for spending/portfolio charts.
- **Training:** `training.html` (renamed from Fitness/`gym.html`) — gym + soccer training planner. No WHOOP/recovery/sleep/HRV. Editable data in `localStorage` `jg_training_data_v1`. Uploaded `.mp4` blobs in IndexedDB `jg_training_videos_v1`, and (when signed in) also in Supabase Storage bucket `training-videos` via `js/training-blobs.js` so phone and laptop can both play. Run `supabase/migrations/002_training_videos_storage.sql` once. Open Training on the **upload device while signed in** to backfill older local-only videos; then Sync / play on the other device.
- **Health:** `health.html` — same dashboard shell as Projects (sidebar + cards). WHOOP metrics are placeholders (`Connect WHOOP` toggles sample/loading/error states only; no real API). Therapy panels are marked sensitive. **Privacy** requires a 4-digit PIN on first use; only a PBKDF2-SHA256 salted hash is stored in `localStorage` (`jg_health_privacy_pin_v1`), never the plaintext PIN. Unlock always prompts for the PIN. Locked state persists across refresh (`jg_health_privacy_locked_v1`). **Therapy / Nutrition / Planning & habits** are fully editable (add/edit/remove); data persists in `localStorage` key `jg_health_data_v1`. Clear that key to reset sample content.
- **Cloud sync:** Core sync uses table `public.user_kv` (`supabase/migrations/001_user_kv.sql`). Training video **bytes** also use Storage bucket `training-videos` (`002_training_videos_storage.sql`) via `js/training-blobs.js`. `js/sync.js` mirrors allowlisted `localStorage` keys when signed in. **Sign in once**; afterward sync runs on save, on tab focus, **every 60s**, and via the Sync button (no need to re-auth each time). Media/Finance/Training/Health/Projects/Habits/Goals **merge by item id** (Main daily goals also merge by task text when ids are missing) so two devices adding different items keep both. **Deletes use a `tombstones` map** on every synced collection (Media, Habits, Projects, Finance, Training, Health, Main goals) so removals stay removed after id-union merge — without tombstones, sync was resurrecting deleted cards. Habits / Projects / Goals store shape is `{ items, tombstones }` (legacy bare arrays are migrated). Empty lists are valid user state (no sample re-seed after delete-all). Training Video Library defaults to `[]` and also purges legacy `*placeholder*` titles without blobs. Health meal slots use `meal:<slot>` tombstone keys. Use the JWT **anon** key in `js/config.js`. Synced keys: `goals:*`, `goal_streak_v1`, `habits_v1`, `projects_v1`, `jg_finance_data_v1`, `jg_training_data_v1`, `jg_health_data_v1`, `jg_media_data_v1` (covers Media hub + Visual Bookmarks + Watchlist + Reading List). Excludes theme + health PIN. Media image IndexedDB blobs are **not** synced yet; Training `.mp4` blobs sync via Storage when signed in. Main/Media pages listen for `jg-sync-complete` to refresh after quiet auto-sync.
- **Mobile hamburger:** Overlay must live **inside** `.app` (same stacking context as the sidebar). If the overlay is a body-level sibling of `.app`, its `z-index` paints above the whole app and steals taps from sidebar section links. Sidebar `z-index` ~50, overlay ~40 on small screens.
- **Auth:** `signin.html` + `js/lock.js`. Prefer **email + password** for Desktop/phone sync testing (passkeys/magic links require production origin `jg-dash-nine.vercel.app`, not localhost). If `js/config.js` has empty `SUPABASE_URL` / `SUPABASE_ANON_KEY`, lock **soft-skips** so local demos work. Passkeys need Supabase Passkeys enabled, RP ID matching the serve host (`localhost` or the Vercel hostname), and HTTPS/localhost (WebAuthn will not run on `file://`).
- Client opt-in: `auth.experimental.passkey: true` in `js/supabase-client.js`. **`registerPasskey()` requires an existing session**. Default Supabase email is a **magic link**: open on same device → `signin.html` → register passkey. `js/config.js` `SITE_URL` drives `emailRedirectTo`. If confirm emails still go to localhost, change Supabase **Authentication → URL Configuration → Site URL** to the Vercel origin (Passkeys RP settings do not control email links). Allowlist Redirect URLs: `https://jg-dash-nine.vercel.app/**`.
- Goals day boundary is **6 AM** local; awake ring window is **8:00 AM → midnight**. Polish button needs `ANTHROPIC_API_KEY` set inside `main.html` (empty → add as-typed).
- Theme (light/dark): `js/theme.js` + topbar **Light/Dark** button (left of Sign out). Stored in `localStorage` key `jg_theme`. Keep theme.js free of MutationObservers — they can freeze the page if button label updates re-trigger observers.
