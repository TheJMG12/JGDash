# AGENTS.md

## Cursor Cloud specific instructions

- This is a **static multi-page site** (no npm app, no build). From `/workspace`, serve with `python3 -m http.server 8765` (or any static server).
- **Goals UI:** open `main.html` — fully self-contained (inline CSS/JS, `localStorage`). Works on `file://` for demos.
- **Hub:** `index.html` bento grid → `main.html`, `training.html`, `health.html`, `media.html`, `finance.html`, `projects.html`.
- **Media:** `media.html` hub is Capture/Inbox (Capture opens a popup form) + Faved-style Bookmark Library (nested tags with `/`, pin, rollup, card/list/table; **Library tags live in the sidebar dropdown**, not a main-panel). Spaces: `visual-bookmarks.html` (**MyMind** — masonry grid stays **2 columns on mobile**; top bar is **search / upload / save** only; mode chips + filters open under search; item tap opens an internally scrollable detail sheet with TLDR, mind tags, notes, favorite, Top of Mind, delete), `watchlist.html`, `reading-list.html`. Pasting a URL auto-fills via `JGMedia.enrichMeta`. Data in `localStorage` `jg_media_data_v1`. Stock filler bookmarks/MyMind samples are purged on load + sync (`JGMedia.purgeSeedContent`). **Phone/image uploads** go through `JGMedia.ingestImageFile` (durable data URL + IndexedDB `blobId`) and, when signed in, Supabase Storage bucket `media-images` via `js/media-blobs.js` so other devices can download previews. Migration: `supabase/migrations/003_media_images_storage.sql` (SQL Editor often returns **Success. No rows returned** for DDL — that is expected; confirm bucket `media-images` under Storage). Open MyMind on the **upload device while signed in** to backfill older local-only images; then Sync on the other device. Never persist raw `blob:` URLs. RSS uses rss2json / allorigins proxies — some feeds may fail CORS.
- **Finance:** `finance.html` — budgeting, purchases, goals, investing, stock analyzer. Manual finance data in `localStorage` `jg_finance_data_v1`. Live quotes via Finnhub when `JGDASH_CONFIG.FINNHUB_API_KEY` is set; otherwise sample/demo market data. Chart.js for spending/portfolio charts.
- **Training:** `training.html` (renamed from Fitness/`gym.html`) — gym + soccer training planner. No WHOOP/recovery/sleep/HRV. Editable data in `localStorage` `jg_training_data_v1`. Uploaded `.mp4` blobs in IndexedDB `jg_training_videos_v1`, and (when signed in) also in Supabase Storage bucket `training-videos` via `js/training-blobs.js` so phone and laptop can both play. Run `supabase/migrations/002_training_videos_storage.sql` once. Open Training on the **upload device while signed in** to backfill older local-only videos; then Sync / play on the other device. **Weekly schedule** uses `scheduleWeekKey` and advances at **Sunday 10:00 PM local** (grid shows the new empty week; prior chips are **not** deleted — they remain in `sessions` / Training history). Mid-week chips never auto-delete. **Session types** when adding: Fitness, Soccer training, and **Game / Match** (`domain: 'game'` — opponent, competition, result, score). **Workout templates** are user-created (`workoutTemplates[]`) from the Exercise library — click or drag onto a day to add a chip with those exercises copied in. Stock fitness string presets and the Current cycle / Recent completed / Planned fitness sessions cards are gone.
- **Health:** `health.html` — same dashboard shell as Projects (sidebar + cards). WHOOP live metrics via `js/whoop.js` + Vercel `api/whoop-*.js`. Connect uses OAuth (Client ID in `js/config.js` only). Sync pulls recovery / cycle / sleep / workouts (~4 API calls), caches **15 minutes**, enforces client buffers **80/min** and **8000/day** under WHOOP’s 100/min · 10000/day caps. Tokens stay in browser `localStorage` (`jg_whoop_tokens_v1`); metrics cache `jg_whoop_metrics_v1`. Required Vercel env: `WHOOP_CLIENT_ID`, `WHOOP_CLIENT_SECRET`, `WHOOP_REDIRECT_URI`. Therapy panels are marked sensitive — Personal and Couples each show a single **Notes** card with a **Topics, Goals, Focus** textarea (`therapy.*.notes.topicsGoalsFocus`). Older therapy list/appointment keys remain in the blob for sync compatibility but are not shown. **Privacy** requires a 4-digit PIN on first use; only a PBKDF2-SHA256 salted hash is stored in `localStorage` (`jg_health_privacy_pin_v1`), never the plaintext PIN. Unlock always prompts for the PIN. Locked state persists across refresh (`jg_health_privacy_locked_v1`). **Therapy / Nutrition / Planning & habits** share one synced blob `jg_health_data_v1` (no auto demo seed — empty until you save or cloud pulls). Health listens for `jg-sync-complete` to re-render after quiet sync. **Meal plan nav:** sidebar **Meal plan** / **Nutrition** and the Meal plan panel tab call `goToMealPlanner()` — they must scroll to `#mealPlannerCard` (not only `#sec-nutrition`), because desktop scrolls inside `#mainScroll` and mobile often scrolls the window; sticky topbar needs ~72px offset. The weekly planner card sits above the calorie target cards so the Meal plan tab leads with the grid. Recipes use `instructions` (not cuisine) on add/edit. **Habit tracker** week is Mon–Sun and resets to all red **Monday 7:00 AM America/New_York** (`habits.weekKey` + track `pattern` / `updatedAt`). **Water intake** lives in `habits.water` `{ cups, date, updatedAt }`, starts at 0 cups, and resets at **local midnight**; re-tap the current cup level clears to none. Sync merges water by date/updatedAt and habit weeks by newer `weekKey`.
- **Cloud sync:** Core sync uses table `public.user_kv` (`supabase/migrations/001_user_kv.sql`). Training video **bytes** also use Storage bucket `training-videos` (`002_training_videos_storage.sql`) via `js/training-blobs.js`. MyMind image **bytes** use Storage bucket `media-images` (`003_media_images_storage.sql`) via `js/media-blobs.js`. `js/sync.js` mirrors allowlisted `localStorage` keys when signed in. **Sign in once**; afterward sync runs on save, on tab focus, **every 60s**, and via the Sync button (no need to re-auth each time). Media/Finance/Training/Health/Projects/Habits/Goals **merge by item id** (Main daily goals also merge by task text when ids are missing) so two devices adding different items keep both. **Health scalars** (therapy appointment/mood/journal, nutrition targets/meal titles, habit notes) resolve by **key mtime LWW**. The old auto-seed (“Dr. Elena Vargas”, etc.) is treated as non-data on both local and cloud — sync discards it and pushes a purge so it cannot keep coming back. **Deletes use a `tombstones` map** on every synced collection (Media, Habits, Projects, Finance, Training, Health, Main goals) so removals stay removed after id-union merge — without tombstones, sync was resurrecting deleted cards. Habits / Projects / Goals store shape is `{ items, tombstones }` (legacy bare arrays are migrated). Empty lists are valid user state (no sample re-seed after delete-all). Training Video Library defaults to `[]` and also purges legacy `*placeholder*` titles without blobs. Health meal slots use `meal:<slot>` tombstone keys — **re-adding to a slot must clear that tombstone** (`healthReviveMealSlot` / `setMealSlot`); sync also drops a meal tombstone when the newer device still has that slot filled (`reconcileMealSlotTombs`). Use the JWT **anon** key in `js/config.js`. Synced keys: `goals:*`, `goal_streak_v1`, `habits_v1`, `projects_v1`, `jg_finance_data_v1`, `jg_training_data_v1`, `jg_health_data_v1`, `jg_media_data_v1` (covers Media hub + MyMind + Watchlist + Reading List). Excludes theme + health PIN. Media image bytes sync via Storage when signed in (same idea as Training `.mp4`). Main/Media/Health pages listen for `jg-sync-complete` to refresh after quiet auto-sync.
- **Mobile hamburger:** Overlay must live **inside** `.app` (same stacking context as the sidebar). If the overlay is a body-level sibling of `.app`, its `z-index` paints above the whole app and steals taps from sidebar section links. On small screens `js/topbar.js` fixes `.mobile-bar` under the sticky topbar (`position: fixed; top: var(--jgdash-topbar-height)`) because `position: sticky` fails when `.main` uses `overflow: hidden`. The drawer `.sidebar` is offset below topbar + mobile-bar so Overview is not covered; `#hamburger` **toggles** open/close (capture handler in topbar.js). Z-order: MyMind detail `.lightbox` 300 → topbar 200 → mobile-bar 150 → sidebar 140 → overlay 130. (Lightbox must stay above the topbar or the sheet ✕ is untappable on phones.)
- **Auth / owner-only:** `signin.html` + `js/lock.js`. App pages stay **hidden** until a session exists and the user matches `OWNER_EMAILS` / `OWNER_USER_IDS` in `js/config.js`. Soft-skip demos are **disabled** when you want production security — missing config or a non-owner account redirects to sign-in and **wipes** local dashboard data. Public “Create account” is removed; OTP uses `shouldCreateUser: false`. Prefer **email + password** (passkeys/magic links need production origin `jg-dash-nine.vercel.app`). Passkeys need Supabase Passkeys enabled, RP ID matching the serve host, and HTTPS/localhost. **You must also** disable Email sign-ups in the Supabase dashboard and run `004_owner_only_access.sql` + `005_owner_only_storage.sql` — see `SECURITY.md`.
- **Apple Calendar (To Dos):** `api/todos-ics.js` serves ICS at `https://…/api/todos-ics?token=…` (GET + HEAD). **Only tasks with a `time`** are published; times use `TZID=America/New_York` (EST/EDT). Copy the **https** link from To Do List (Test feed first). Vercel env: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. Token in synced `jg_calendar_feed_v1`.
- Client opt-in: `auth.experimental.passkey: true` in `js/supabase-client.js`. **`registerPasskey()` requires an existing session**. Default Supabase email is a **magic link**: open on same device → `signin.html` → register passkey. `js/config.js` `SITE_URL` drives `emailRedirectTo`. If confirm emails still go to localhost, change Supabase **Authentication → URL Configuration → Site URL** to the Vercel origin (Passkeys RP settings do not control email links). Allowlist Redirect URLs: `https://jg-dash-nine.vercel.app/**`.
- Goals day boundary is **6 AM** local; awake ring window is **8:00 AM → midnight**. Polish button needs `ANTHROPIC_API_KEY` set inside `main.html` (empty → add as-typed).
- **Main To Do List:** Completed tasks stay on Today until the next 6 AM boundary, then leave Main’s Today list. Rollover (`js/goals-rollover.js`, used by Main + `todos.html`) migrates **only unfinished** tasks forward (new ids + tombstones on the source day). Completed tasks stay on their original `goals:YYYY-MM-DD` key. After rollover/sync, open copies on Today that duplicate a **completed** task on any past day (same text, e.g. legacy Aug 10 roll-forward) are removed; sync merge also collapses same-text done+open on one day (`dedupeGoalItemsByText` in `js/sync.js`). **Projects → To Do List** (`todos.html`) is the full record of those same `goals:*` keys — edits sync with Main.
- Theme (light/dark): `js/theme.js` + topbar **Light/Dark** button (left of Sign out). Stored in `localStorage` key `jg_theme`. Keep theme.js free of MutationObservers — they can freeze the page if button label updates re-trigger observers.
